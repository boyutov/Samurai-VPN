# WireGuard на Linux — версия 0.3

На Linux добавлены подключение, отключение и чтение состояния настоящего
WireGuard-интерфейса. Проверен обмен ключами и ICMP в обе стороны между двумя
изолированными сетевыми пространствами. Это ещё не проверка игры через интернет.
Windows — см. docs/WINDOWS.md, macOS — docs/MACOS.md.

## Устройство

Окно работает от обычного пользователя. Команды с правами администратора выполняет
отдельный Java-компонент в /opt/samurai-vpn-helper. Он устанавливается вместе со
своим runtime; системная Java для работы готовой сборки не нужна.

Компонент принимает через stdin только up, down и status для UUID сети.
Ключи не передаются в аргументах процессов или через временные конфигурации.
Для изменения сети используются фиксированные пути к ip и wg, без запуска shell.
Установочный launcher очищает окружение перед запуском Java.

Имя интерфейса sm… определяется по UID владельца и UUID сети. Метка ifalias
связывает его с владельцем. Уже существующий чужой интерфейс не изменяется.
Команды разных окон сериализуются через закрытый root-каталог /run/samurai-vpn.

## Подготовка компонента

На текущем компьютере комплект dist/helper уже подготовлен. Для пересборки:

    ./build.sh
    ./package-helper.sh

Упаковщик создаёт новую папку и отказывается перезаписывать существующую.
Необходимы Linux с поддержкой WireGuard в ядре, iproute2, wireguard-tools, pkexec
и работающий графический агент polkit в пользовательской сессии.

Проверьте исходники vpn-linux и native/linux/install-helper.sh. Установка:

    sudo ./native/linux/install-helper.sh

Установщик создаёт только /opt/samurai-vpn-helper с владельцем root и запрещает
запись обычным пользователям. Интерфейсы, firewall, автозапуск и правила
беспарольного повышения прав при установке не создаются.
Существующий компонент не заменяется автоматически.

### Служба samurai-vpnd (рекомендуется)

Без службы каждое действие требует пароль через pkexec, а прямые соединения
недоступны: весь трафик пар за NAT идёт через relay. Служба устанавливается после
компонента:

    sudo ./native/linux/install-daemon.sh

- Работает от временного пользователя systemd (DynamicUser) с единственной
  возможностью CAP_NET_ADMIN, без root. Файлы unit: native/linux/samurai-vpnd.service.
- Принимает запросы через /run/samurai-vpnd/daemon.sock. UID вызывающего берётся
  из ядра (SO_PEERCRED); пользователь управляет только своими интерфейсами sm….
- Операции: up, down, status, endpoint и sync. endpoint меняет адрес только у уже
  настроенного участника и не может добавить новый ключ или маршрут.
- sync приводит работающий туннель к текущему составу сети без переподключения:
  удаляет ключи и маршруты отозванных участников, добавляет новых (только /32 из
  10.203.N.0/24 своей сети, с той же проверкой конфликтов маршрутов). Работающие
  соединения и выбранные пути не трогаются. Приложение вызывает sync, когда список
  на сервере (проверяется каждые 30 секунд) отличается от туннеля.
- Запросы выполняются по одному; размер запроса до 64 КБ, время до 30 с,
  не больше 16 соединений одновременно.
- Удаление: sudo systemctl disable --now samurai-vpnd, затем удалить
  /etc/systemd/system/samurai-vpnd.service.

**На рабочую систему компонент и служба при разработке автоматически не устанавливались.**
Unit проверен systemd-analyze, но запуск службы на настоящей системе ещё не проверен.
Диалог polkit и установленный компонент на обычном рабочем столе ещё нужно
проверить; тестирование движка выполнялось в изолированных пространствах.

## Подключение

1. Запустите dist/SamuraiVPN/bin/SamuraiVPN обычным пользователем.
2. Откройте профиль реальной сети. Сервер должен быть доступен по HTTPS;
   локальный HTTP подходит только для одного компьютера.
3. Зарегистрируйте друга. Хотя бы одна сторона должна иметь доступный UDP
   endpoint, опубликованный при регистрации. Проброс NAT здесь не реализован.
4. Нажмите «Подключить» и укажите локальный UDP-порт WireGuard.
5. Проверьте план: адрес /32, маршруты к конкретным участникам, порт, MTU 1280.
6. Подтвердите план, затем системный запрос администратора от pkexec.
7. Кнопка «Проверить туннель» показывает состояние интерфейса, время последнего
   обмена ключами и суммарные счётчики. Для неё тоже требуется системное разрешение.

DNS, основной маршрут интернета и firewall не меняются. Добавляются только
маршруты /32 к участникам. Пересечение с существующими специфическими IPv4-маршрутами
или локальными подсетями блокирует подключение. MTU пока фиксирован, его
автоматическое определение не реализовано.

Надпись «интерфейс включен» не означает, что друг или игра доступны. Старое время
handshake также не доказывает доступность сейчас. У всех участников должны быть
актуальные ключи, разрешённый UDP-трафик и корректные endpoint.

## Отключение и обновление

Туннель продолжает работать после закрытия окна. Нажмите «Отключить» перед выходом,
если он больше не нужен. Для отключения сервер не требуется: достаточно
сохранённого профиля. При перезагрузке интерфейсы исчезают; автозапуска нет.

Со службой samurai-vpnd и открытым окном новые и удалённые участники применяются
к туннелю автоматически примерно за 30 секунд. Relay перестаёт пересылать трафик
удалённого участника сразу. Без службы или при закрытом окне после изменения
состава отключите и заново подключите туннель на остальных устройствах.

При обычной ошибке настройки компонент удаляет только созданный им интерфейс
вместе с его маршрутами. Принудительное завершение процесса или тайм-аут клиента
могут оставить состояние неизвестным: сначала проверьте туннель, не повторяйте
подключение вслепую. Восстановление после аварий между системными командами
пока не автоматизировано.

Для обновления или удаления компонента сначала отключите все его туннели.
Папку /opt/samurai-vpn-helper затем удаляет администратор. При обновлении
установите новый комплект повторно. Пароли приложения не собираются:
аутентификация проходит через системный polkit.

## Изолированная проверка

    sudo modprobe nft_masq
    sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
    xvfb-run -a ./native/linux/test-isolated.sh -Dsamurai.gui.test=true
    sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=1

Ubuntu 23.10+ через AppArmor запрещает user namespaces без прав администратора:
sysctl снимает запрет до перезагрузки, последняя строка возвращает его. Модули
ядра внутри user namespace не загружаются, поэтому nft_masq (для NatTraversalTest)
загружается заранее. Скрипт проверяет оба условия и подсказывает команду.

Сам скрипт создаёт отдельные user/network namespaces без sudo. Внутри создаются два
дочерних network namespace, veth-связь и два WireGuard-интерфейса. Проверяются
handshake, ping в обе стороны, прекращение связи после отключения, сохранность
исходных маршрутов и откат после принудительной ошибки. Завершение теста удаляет
эти пространства. Тест отказывается работать без признаков изоляции.

Обычный mvn verify запускает проверки ограничений и пропускает тест с настоящими
интерфейсами. Некоторые системы запрещают unprivileged user namespaces:
не заменяйте тестовый запуск на sudo в основном сетевом пространстве.
