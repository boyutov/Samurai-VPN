# Samurai VPN

Java-проект частных игровых сетей для Windows, Linux и macOS.

**Статус: preview 0.3, для разработки и лабораторных проверок.**
Работают сервер, консольный клиент и графическое приложение на Java Swing.
Клиент генерирует ключи и профили WireGuard. На Linux туннель включается из окна
через отдельный root-компонент (см. docs/LINUX.md). Сервер может пересылать
зашифрованный WireGuard-трафик участников за NAT (relay, см. docs/RELAY.md).
Подключённый туннель обслуживает фоновый агент пользователя, в том числе после закрытия
окна: он применяет новых и удалённых участников и пробует прямое соединение (hole
punching) с возвратом на relay. Для этого нужна служба туннеля: samurai-vpnd на Linux,
служба Samurai VPN на Windows и macOS (docs/AGENT.md).
С параметром `--state-file` сервер сохраняет сети, участников, приглашения и порты relay
в файл и восстанавливает их после перезапуска.
Проект пока не является готовой заменой Radmin VPN и не проходил независимый аудит безопасности.

## Установщики

Каждая сборка CI (GitHub Actions → прогон → Artifacts) выкладывает установщики:
`samurai-vpn_*.deb` (Linux), `SamuraiVPN-*.pkg` (macOS), `SamuraiVPN-*-setup.exe` (Windows).
Каждый из них в CI устанавливается, проверяется настоящим туннелем через службу и
удаляется. Собрать локально: `./build.sh` (на Windows `mvn install`), затем
`./package-installer.sh` или `./package-installer.ps1`. Установщики не подписаны.
Подробности: docs/LINUX.md, docs/WINDOWS.md, docs/MACOS.md.

## Открыть в IntelliJ IDEA

`File → Open → samurai-vpn/pom.xml → Open as Project`.
В `Project SDK` и в Maven Runner выбрать **JDK 21**. Корневой Maven-проект содержит
все четыре модуля; импортировать каждый отдельно не нужно.

## Запуск приложения

Готовая Linux-сборка с Java внутри запускается командой:

    ./dist/SamuraiVPN/bin/SamuraiVPN --demo

Отдельная установка Java для этой сборки не требуется. Папку SamuraiVPN нужно
сохранять целиком: рядом с исполняемым файлом находятся библиотеки и среда Java.
Эта сборка предназначена для Linux x86_64 и проверена на текущем компьютере;
совместимость с другими дистрибутивами и архитектурами ещё требует проверки.

При разработке, после Maven-сборки:

    ./samurai.sh desktop
    ./samurai.sh desktop --demo

На Windows: ./desktop.ps1 --demo (требует настроенного JDK 21).
На любой ОС с Java 21: java -jar vpn-desktop/target/samurai-desktop.jar --demo.
В IDEA можно запустить dev.samurai.vpn.desktop.DesktopMain.

Приложение умеет создавать сеть на работающем сервере с admin.token,
присоединяться по приглашению, показывать участников, сохранять профиль WireGuard,
создавать приглашения и удалять участников от имени владельца.
Для подключения к реальному серверу потребуется HTTPS и его доверенный сертификат.

Профили сохраняются в ~/.samurai-vpn, каждый в новой папке. Расположение меняется
аргументом --data-dir PATH. «Открыть профиль» выбирает папку с session.json и,
для владельца, owner.json. Приватные ключи не показываются в окне.
Существующие файлы не перезаписываются. При прерванном входе частичные файлы
остаются для восстановления; не удаляйте их, пока не выяснили результат запроса.

Кнопка «Демонстрация» запускает свой сервер на случайном loopback-порту и создаёт
два тестовых устройства. Закрытие окна останавливает этот сервер после завершения
текущего запроса. Демонстрация не передаёт игровой трафик и не меняет сеть ОС.
После закрытия её профили сохраняются, но сервер уже недоступен: для новой
демонстрации нажмите кнопку в новом окне. Внешний сервер окно не останавливает.
Список участников отражает регистрацию, а не статус онлайн.

## Сборка с Java внутри

Для разработчика требуются JDK 21 с jpackage и Maven. На Linux/macOS:

    ./build.sh
    ./package.sh

На Windows: mvn verify, затем ./package.ps1.
Можно указать новую папку результата: ./package.sh dist-next.
Существующий комплект не перезаписывается.

Упаковщик создаёт папку приложения через jpackage. На Windows точка входа —
SamuraiVPN.exe, на macOS — SamuraiVPN.app, на Linux — bin/SamuraiVPN.
Каждая сборка создаётся на своей ОС и для своей архитектуры.
Windows/macOS проверены в CI на настоящих системах (туннель, маршруты, sync), но не на
устройствах пользователей. Для туннелей на Windows
нужны WireGuard for Windows и служба Samurai VPN (docs/WINDOWS.md), на macOS —
wireguard-go и служба Samurai VPN (docs/MACOS.md). Установщики и подписи
ещё не добавлены. Встроенный runtime нужно обновлять вместе с приложением.
WireGuard и системный VPN-адаптер пока в комплект не входят.

Документация инструмента: https://docs.oracle.com/en/java/javase/21/docs/specs/man/jpackage.html

Проверка встроенного runtime: ./dist/SamuraiVPN/bin/SamuraiVPN --self-test.
Она создаёт временную локальную сеть, проверяет ключи и экспорт, затем удаляет
свои временные файлы и останавливает сервер.

## Сборка

Требуются JDK 21+ и Maven 3.9+. В терминале `java -version` и `mvn -version`
должны показывать Java 21 или новее. Наличие JDK 21 в IDEA само по себе не меняет
Java терминала.

Linux на текущем компьютере (скрипт найдёт установленный JDK 21):

```bash
./build.sh
```

Любая из трёх ОС, с настроенным `JAVA_HOME`:

```text
mvn -B verify
java -jar vpn-client/target/samurai-client.jar --help
java -jar vpn-server/target/samurai-server.jar --help
```

Готовые JAR включают зависимости. Для запуска нужен JRE/JDK 21+.
Тесты проверяют регистрацию двух клиентов через HTTP, HTTPS с реальным сертификатом,
отклонение неверного имени сервера и недоверенного сертификата, изоляцию сетей,
одноразовые приглашения, отзыв членства и ограничения конфигураций.
CI (GitHub Actions) собирает и тестирует проект на Linux, Windows и macOS; на Windows
и macOS он поднимает настоящий туннель WireGuard (-Dsamurai.system.test=true).
Эти системные тесты запускать только на одноразовой машине.

## Локальная демонстрация

После сборки на Linux/macOS:

```bash
./demo.sh
```

На Windows PowerShell:

```powershell
./demo.ps1
```

Демонстрация запускает локальный сервер на `127.0.0.1:8787`, создаёт сеть и двух
участников, экспортирует профили, останавливает сервер. Файлы сохраняются в новой
подпапке `.local/demo-*`. Она не меняет сетевые интерфейсы, маршруты или firewall.
У демонстрационных профилей нет доступных сетевых endpoint, поэтому они
демонстрируют управление сетью, а не передачу игровых пакетов.

## Ручной сценарий

Команды одинаковы на Windows, Linux и macOS. На Linux/macOS можно использовать
`./samurai.sh client ...` и `./samurai.sh server ...` вместо `java -jar ...`.

Сначала создать токен администратора (один раз):

```text
java -jar vpn-client/target/samurai-client.jar gen-admin --out .local/admin.token
```

В первом терминале запустить сервер для локальных тестов:

```text
java -jar vpn-server/target/samurai-server.jar --dev --admin-token-file .local/admin.token --state-file .local/server-state.json
```

Без `--state-file` состояние хранится только в памяти и пропадает при остановке сервера.
Файл состояния содержит только хэши токенов (сами токены не сохраняются), открытые ключи,
имена, адреса и endpoint участников; он создаётся с правами 600. Каждое изменение
записывается целиком во временный файл и атомарно заменяет старый, так что при сбое
остаётся либо прежнее, либо новое состояние. Если записать не удалось, запрос получает
503 и ничего не меняется. Второй сервер с тем же файлом не запустится. Повреждённый или
изменённый вручную файл сервер не перезаписывает, а отказывается запускаться.
Резервная копия — обычная копия этого файла.

Во втором терминале:

```text
java -jar vpn-client/target/samurai-client.jar create-network --dev --server http://127.0.0.1:8787 --token-file .local/admin.token --name Friends --out .local/owner.json
java -jar vpn-client/target/samurai-client.jar keygen --out .local/alice-key.json
java -jar vpn-client/target/samurai-client.jar invite --dev --owner .local/owner.json --out .local/alice-invite.json
java -jar vpn-client/target/samurai-client.jar join --dev --invite .local/alice-invite.json --identity .local/alice-key.json --name Alice --out .local/alice.json
```

Для второго участника повторить `keygen`, `invite`, `join` с новыми именами файлов.
Для реального прямого туннеля при `join` указать `--endpoint IPv4:PORT` — доступный
UDP-адрес устройства, например LAN-адрес на общей физической сети. На разных сетях
может потребоваться ручная настройка перенаправления порта. Текущая версия
не определяет внешний адрес и не пробивает NAT автоматически.

После регистрации обоих участников:

```text
java -jar vpn-client/target/samurai-client.jar peers --dev --session .local/alice.json
java -jar vpn-client/target/samurai-client.jar export --dev --session .local/alice.json --out .local/alice.conf
```

На каждом устройстве импортировать **свой** `.conf` в установленный WireGuard.
После настройки доступности UDP endpoint и firewall игра подключается к
виртуальному IP хоста и порту, который сообщает игра. Minecraft LAN discovery
через broadcast/multicast в этой версии не поддерживается; использовать прямой IP.
Подсеть `10.203.0.0/16` зарезервирована для прототипа: перед применением профилей
проверить отсутствие пересечения с локальными/корпоративными маршрутами.

## HTTPS для нескольких компьютеров

`--dev` разрешает HTTP только на loopback и не подходит для удалённых клиентов.
Нужен PKCS#12 с сертификатом, доверенным клиентской JVM, и корректным SAN имени
сервера. Задать `SAMURAI_TLS_PASSWORD` в окружении и запустить:

```text
java -jar vpn-server/target/samurai-server.jar --bind 0.0.0.0 --port 8787 --admin-token-file .local/admin.token --tls-keystore .local/server.p12
```

Клиенту передавать `https://имя-сервера:8787`, без `--dev`.
Для внутреннего CA можно использовать стандартный truststore JVM, например
`-Djavax.net.ssl.trustStore=...` и `-Djavax.net.ssl.trustStoreType=PKCS12`.
Режима отключения проверки сертификатов нет. Сервер 0.1 предназначен для
контролируемой тестовой среды; публичное размещение отложено до выполнения
[критериев выпуска](docs/ROADMAP.md).

## Файлы с секретами

- `admin.token`: разрешает создавать сети. Не передавать участникам.
- `owner.json`: позволяет приглашать и удалять участников конкретной сети.
- `*-invite.json`: одноразовое приглашение, действительно 10 минут; передавать доверенным каналом.
- `*-key.json`, `*.json` с сессией и `*.conf`: содержат приватный ключ устройства.

Файлы создаются без перезаписи, с правами `0600` на POSIX и ограниченным ACL
на Windows. После передачи приглашения на Linux/macOS установить `chmod 600`.
Сервер получает только публичные WireGuard-ключи; bearer-токены хранит в виде
SHA-256-хешей. Секреты не передаются в аргументах команд или URL.
При ошибке запроса может остаться пустой зарезервированный выходной файл:
для повторной попытки выбрать новое имя. При потере ответа на `join` владелец
должен удалить «осиротевшего» участника перед повторной регистрацией того же ключа.

## Структура

```text
vpn-core/    DTO, проверка входа, ключи, генерация профилей, защищённые файлы
vpn-server/  HTTP(S) API, права владельца/участника, приглашения, распределение IP
vpn-client/  консольные команды, локальные ключи и сессии, HTTP(S)-клиент
vpn-desktop/ окна Swing, папки профилей и локальная демонстрация
docs/        архитектура, модель угроз, API и план следующих этапов
```

Java управляет приложением. Шифрование пакетов и виртуальный сетевой интерфейс
предоставляет WireGuard: [интеграция по ОС](https://www.wireguard.com/embedding/),
[официальная настройка](https://www.wireguard.com/quickstart/).
Самописный VPN-протокол или реализация криптографии в проект не включены.

GUI-тест на Linux с Xvfb: xvfb-run -a ./build.sh -Dsamurai.gui.test=true.
Без этого параметра проверка окна пропускается в среде без дисплея; сценарии
сервера и desktop-профилей выполняются всегда. Скриншоты можно сохранить,
добавив -Dsamurai.gui.capture=target/screenshots.

Ключевые ограничения: без `--state-file` серверное состояние теряется при перезапуске; отзыв
участника блокирует API сразу, но уже импортированные WireGuard-профили нужно
перегенерировать и применить на всех оставшихся устройствах. Перезапуск сервера
также не выключает ранее активированные туннели. Подробности — [SECURITY.md](SECURITY.md).
